# Audit RL Simulator

Автономная учебная среда для задачи FinTech: воспроизводимые синтетические бухгалтерские эпизоды, инструменты расследования, скрытый эталон, matcher и терминальная награда. Все компании, люди, документы и суммы вымышлены.

> Это стартовая реализация требований задания, а не профессиональное аудиторское заключение и не доказательство пригодности к реальному аудиту. До сдачи на хакатон необходимо прогнать и расширить тесты, особенно бухгалтерскую согласованность и независимую проверку эталонов.

## Требования

* Python 3.11+
* Без сети, GPU и платных API
* Установка для тестов: `python -m pip install -e ".\[dev]"`

## Быстрый запуск

```bash
python -m pip install -e ".\[dev]"
pytest -q
python -m audit\_rl\_sim.cli --seed 7 --policy reconcile
```

Другие базовые политики:

```bash
python -m audit\_rl\_sim.cli --seed 7 --policy random
python -m audit\_rl\_sim.cli --seed 7 --policy reconcile --clean
python -m audit\_rl\_sim.cli --seed 7 --policy mark-all --interacting
```

По умолчанию создаётся `trajectories.jsonl`.

## Структура

* `audit\_rl\_sim/generator.py` — детерминированная генерация открытых записей и закрытого truth/provenance.
* `audit\_rl\_sim/env.py` — `reset(seed, config)` и `step(action)`, пять разрешённых инструментов, лимиты.
* `audit\_rl\_sim/evaluator.py` — взаимно-однозначное сопоставление и формула награды.
* `audit\_rl\_sim/policies.py` — случайная, простая, mark-all и evaluator-only oracle политики.
* `audit\_rl\_sim/data/train/`, `audit\_rl\_sim/data/dev/` — открытые эпизоды.— открытые эпизоды.
* `tests/` — базовые тесты контракта, изоляции, калькулятора и награды.

## API

```python
from audit\_rl\_sim import AuditEnv

env = AuditEnv(reveal\_reward=True)  # False для закрытого прогона
observation, info = env.reset(seed=123, config={"clean": False})
observation, reward, terminated, truncated, info = env.step({
    "tool": "list\_records", "table": "ledger", "cursor": None, "limit": 20
})
```

Допустимые `tool`: `list\_records`, `get\_record`, `get\_document`, `calculator`, `submit`.
Размер страницы — максимум 50; максимум 100 шагов, включая submit; бюджет времени — 60 секунд. Ошибки инструмента расходуют шаг. При закрытой оценке награда остаётся нулевой в агентском интерфейсе.

## Награда

`clip(2 \* F1 - 1 - 0.002 \* inspection\_steps, -1, 1)`

В `F1` учитываются тип, канонические `affected\_ids`, сумма с допуском, валюта и полный допустимый набор доказательств. Повторные выводы не создают TP.

## Данные

Публичные файлы эпизода: `manifest.json`, `ledger.csv`, `invoices.jsonl`, `payments.jsonl`, `fx.csv`, `policy.json`.
Закрытые файлы оценщика: `truth.json`, `provenance.json`. Не передавайте их агенту, не включайте в наблюдения и не записывайте в обучающие траектории.

## Ограничения текущей версии

1. Генератор покрывает четыре семейства ошибок и синтетические отвлекающие случаи, но бухгалтерские сценарии и FX-модель пока упрощены.
2. `OraclePolicy` намеренно использует закрытый truth и предназначена исключительно для локального smoke-test/верхней границы; её нельзя запускать как обычного агента.
3. Парные проверки перестановок/переименования ID, полная валидация схем и независимый аудит каждой синтетической книги должны быть расширены перед официальной сдачей.
4. Экспорт truth/provenance — evaluator-only метод; в реальной архитектуре оценщик должен находиться в отдельном процессе.

## Версия и воспроизводимость

Версия пакета `0.1.0`. Генератор использует локальный `random.Random(seed)` и не меняет глобальное состояние генератора случайных чисел.
